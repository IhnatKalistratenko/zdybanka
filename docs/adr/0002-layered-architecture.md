# Zdybanka — Layered Architecture

## Загальна інформація

Backend застосунку **Здибанка** розроблено у вигляді модульного моноліту. Кожен модуль відповідає за окрему частину функціональності системи. Взаємодія між модулями відбувається через чітко визначені інтерфейси.

Архітектура backend-застосунку побудована на основі шарової архітектури (*Layered Architecture*), яка передбачає розподіл відповідальності між окремими шарами.

## Структура шарів

Backend-застосунок складається з таких шарів:

* **Core** — доменні моделі та основні поняття предметної області.
* **Data** — реалізація доступу до бази даних і налаштування взаємодії з нею.
* **Application** — бізнес-логіка застосунку, організована у вигляді окремих сервісів.
* **API** — вебзастосунок, що забезпечує взаємодію між сервером і клієнтами.
* **Infrastructure** — зовнішні залежності та інтеграції, які не належать до доменної логіки.
* **Tests** — модуль із модульними (*unit*) та інтеграційними (*integration*) тестами.

## Опис шарів

### Core

Центральний шар застосунку, що містить доменні моделі та представляє основні поняття предметної області. Не залежить від інших модулів.

### Data

Шар, що відповідає за реалізацію доступу до бази даних і налаштування підключення до неї. Залежить від шару Core.

### Application

Шар, що містить бізнес-логіку застосунку, організовану у вигляді окремих сервісів. Залежить від шарів Data та Infrastructure.

### API

Шар, що надає клієнтам доступ до функціональності сервера через вебінтерфейс API. Відповідає за обробку вхідних запитів і формування відповідей. Залежить від шарів Application та Infrastructure.

### Infrastructure

Шар, що містить зовнішні залежності та інтеграції, які не належать до доменної логіки застосунку.

### Tests

Шар, що містить модульні та інтеграційні тести для перевірки роботи компонентів застосунку. Може залежати від усіх інших шарів.

## Правила залежностей між шарами

Залежності між шарами визначаються такими правилами:

* **Core** не залежить від жодного іншого модуля.
* **Data** залежить від **Core**.
* **Application** залежить від **Data** та **Infrastructure**.
* **API** залежить від **Application** та **Infrastructure**.
* **Tests** може залежати від усіх інших шарів.
